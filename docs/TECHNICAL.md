# 기술 설명

대상: PS2 일본판 SLPM-65078. 실행 파일 `SLPM_650.78`, 데이터 `MGS2/STAGE.DAT`, `CODEC.DAT`, `DEMO.DAT`, `VOX.DAT`, `MOVIE.DAT`, `FACE.DAT`.

## 문자 인코딩

- 1바이트 `0x00`(끝), `0x0A`(줄바꿈), 그 밖의 `0x20~0x7E` 는 ASCII(가변폭 글꼴).
- 2바이트 코드는 `상위 & ~0x60` 으로 표를 고릅니다. `0x2000/0x4000` 은 루비 괄호·구두점 표시용 플래그입니다.
  - `0x80xx`: ASCII
  - `0x81xx` / `0x82xx` / `0x83xx`: 상주 가나·기호 글꼴(인덱스 lo-1 / lo+0x50 / lo+0xA4)
  - `0x84xx~0x9Bxx`: 0x400 단위 슬롯 6개(슬롯당 1,020자, `0x18d238` 표). 슬롯 2·4는 스테이지 글꼴, 슬롯 3은 자막 청크 글꼴로 쓰입니다.
- 글리프는 24×24 2bpp(144바이트)입니다. 글리프 주소 함수는 `0x115ce8` 입니다.
- 루비는 `#` `{(0xA07B)` 본문 `、(0xC308)` 루비 `}(0xC07D)` `#` 형식입니다. `#` 다음 글자는 제어 코드로 해석됩니다(`0x116c80`).

## 한글 출력

- ELF 의 `0x70000000`(REGINFO) 프로그램 헤더를 PT_LOAD 로 바꿔 `0x90000` 에 코드 훅과 한글 글꼴을 적재합니다. `0x90000~0xFFFFF` 는 게임 실행 중 쓰이지 않는 영역입니다.
- `0x115ce8` 진입부를 `j 0x90000` 으로 바꿨습니다. 상위 바이트가 `0x84~0x8B` 이면 `0x90100 + ((hi-0x84)*255 + lo-1) * 144` 를 반환하고, 그 밖의 코드는 원래 경로로 돌아갑니다.
- 크기가 늘어난 ELF 는 ISO 끝으로 옮기고 디렉터리 레코드(양 엔디언)와 PVD 볼륨 크기를 갱신합니다. 다른 파일의 LBA 는 바꾸지 않습니다.

## STAGE.DAT

- **TOC**: 첫 워드를 키로 하고, 키 xor 0xF0F0 을 증분으로 삼아 다음 12바이트와 항목(이름 8 + 섹터 오프셋 4) 123개를 이어서 복호화합니다.
  - 복호화식: `w ^= key; key = key*0x02E90EDD + inc`
- **스테이지 헤더**: 키를 다음처럼 만들어 복호화합니다. 헤더는 항목 수 n 과 8바이트 항목 n개로 이루어집니다.
  - `a = strcode(이름)`, 해시는 24비트 회전 5 + 문자 가산
  - `key = a*129 + w0 + 0xA78925D9`
  - `inc = a*129 + 0x7A88FB59`
- **헤더 항목 종류**
  - `0x7F0x`: 페이지 시작/끝과 비압축 크기
  - `0x7E`: 압축 크기와 오프셋
  - 그 밖: `유형<<24 | 이름해시`, 페이지 내 오프셋
- **페이지**: 첫 u16 을 시드로 키를 만들어(`k = h^0x9385`) 복호화한 뒤, 첫 u16 에 0x8F3 을 더하면 zlib(1.1.3) 스트림이 됩니다. 마지막 워드까지 4바이트 단위로 처리해야 adler32 가 맞습니다.
- 재패킹할 때는 스테이지 길이를 원본과 같게 맞춥니다(남는 부분은 0으로 채움). TOC 오프셋이 바뀌면 부팅 중 멈춥니다.

## GCX 리소스표 (스테이지 유형 0x06, CODEC.DAT)

- 끝부분의 `[전체][0x10][문자열 오프셋][글꼴 오프셋][항목...]` 표가 리소스표입니다.
  - 항목 상위 비트 1: 문자열
  - 항목 상위 비트 0: 이진 자료
  - 글꼴 블록: `[크기]` 다음에 144바이트 글리프
- 문자열을 다시 쓸 때 이진 자료는 원래의 16바이트 정렬을 유지합니다. 로컬 글꼴이 필요 없으면 글꼴 블록을 비우고, 파일 길이는 원본과 같게 맞춥니다.

## 자막 청크 (DEMO.DAT / VOX.DAT 의 유형 4)

- 구조: `[4][크기][프레임][추가 길이]` 헤더, `[글꼴 오프셋]`, 항목들, 추가 자료, 글꼴 블록 순입니다.
  - 항목 형식: `[시작][끝][화자][길이] + 텍스트`
- 청크 길이를 유지한 채 제자리에서 재구성합니다.

## 그림 속 글자 (스테이지 유형 0x13)

- 0x13 은 스프라이트 텍스처 묶음입니다.
  - 헤더 0x20 바이트 다음에 0xA0 바이트 항목이 이어집니다. 항목에는 UV 사각형, 이름 해시, GIF A+D 로 CLAMP_1·TEX2_1·TEX0_1·ALPHA 등이 들어 있습니다.
  - 자료는 폭 64 CT32 업로드용으로 GS 배치된 이미지이고, 마지막 0xC00 바이트는 CLUT 입니다.
- 텍스처 영역은 항목의 TEX0(TBP·TBW·PSMT4/PSMT8)별로 펼칩니다. 한 묶음에 4bpp 와 8bpp 가 섞일 수 있습니다.
  - 항목이 없는 묶음(스크립트가 직접 그리는 그림)은 128px 페이지 경계의 잉크 연속성이 가장 좋은 폭으로 추정합니다.
- **글자 줄 찾기**: 펼친 영역을 줄 단위로 분할한 뒤 Windows 일본어 OCR 과 그림 판정으로 전수 판정합니다.
- **교체**: 상자 안을 배경 인덱스로 지우고 원래 쓰던 본체·외곽 인덱스로 한글을 그려, 원본 팔레트를 그대로 씁니다.
- **수동 좌표**: 항목이 빽빽한 튜토리얼 아틀라스와 컨트롤러 조작 도해, 두 줄 고지문은 좌표를 직접 지정했습니다.

## 줄바꿈

- 코덱: 폭 410px, 3줄
- 컷신·음성 자막: 폭 480px, `|` 줄바꿈, 2줄
- 스테이지 문자열: 번역문의 `|`·`\n` 구조를 유지하고 한 줄 696px 이하
- 한글 1자는 24px, ASCII 는 글꼴 표 폭 + 1px 로 계산합니다.
